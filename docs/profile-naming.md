# Profile 命名与配置键

## 目标与实现

整条启动配置统一称为 Profile，provider 表示其中的服务商。代码、模板和使用文档采用 `profiles`；新建配置生成 `[[profiles]]` 和 `[profiles.env]`，旧配置仍可读取。

内部集合为 `Config.profiles`，使用 `#[serde(alias = "providers")]` 兼容旧集合键。沿用 Serde 的重复字段检查，同一文件同时使用新旧集合键时拒绝解析，不合并列表，也不丢弃任一组配置。菜单、Recent、启动参数、resume 与环境变量注入逻辑不变。

## 契约变更与影响

| 项目 | 变更与影响 |
|---|---|
| 推荐配置格式 | `[[providers]]` → `[[profiles]]`，`[providers.env]` → `[profiles.env]`。模板和当前文档统一使用新键，使外部配置与 Profile 命名一致。服务商字段仍为 `provider`。 |
| 旧格式兼容 | 0.3.2 同时支持完整的新格式或旧格式，不自动改写用户文件。若混用集合键，或只更新数组而漏改 env 表头，解析失败，避免启动时遗漏配置或环境变量。 |
| 配置诊断 | 字段路径统一采用规范名称 `profiles[index].field`，旧格式校验错误也使用该名称；依赖旧错误文本的调用方需调整，退出码保持不变。 |
| 本机迁移 | 安装 0.3.2 后将实际配置及已注释的示例表头切换为新键；保持每条配置内容、顺序、ID、凭据、启动参数和 recent 不变，并保留旧配置备份。 |
| 回滚兼容 | 0.3.1 及更旧版本不认识新键。回滚二进制时，须同时恢复备份或将两种表头改回旧键；保留旧格式的配置可直接供新旧二进制读取。 |

CLI 参数、启动算法及 recent 持久化格式无变化。**DDL：无变化。** 无缓存、数据版本、重算或调度变更。

## 验证

1. 现有单元与 CLI 测试使用新键，验证列表、详细校验、环境注入、启动、参数透传、resume、Recent、首次模板生成。
2. 新旧格式运行相同命令，对比输出、退出码与 recent；验证未知字段及空字段仍报错，读取不自动改写旧配置。
3. 验证新旧数组混用、数组与 env 表头混用在启动前失败；不执行 agent，也不写 recent。
4. 执行 fmt、clippy、测试、审计、release 构建、打包和 Linux/macOS CI；安装后走查菜单及本机迁移结果。

## 上线步骤

1. 完成上述检查及 PR 合并，发布 0.3.2 到 crates.io 和 GitHub Release。
2. 先安装新版本，再备份和修改本地配置表头；迁移前后解析结果仅顶层集合键变化，其他内容逐项相同。
3. 验收本机 `list` / `list --verbose`、菜单取消及隔离 agent 启动，新旧格式均可用。无需存量批处理、重算或自动任务恢复。
4. 出现问题时恢复旧配置与旧二进制，保留 recent；配置与旧版兼容边界见上表。
